Відповіді на завдання для звіту
1. Делегат у C#, його схожість та відмінність від вказівника на функціюДелегат у C# — це спеціальний тип посилання, який зберігає в собі адресу методу. Він чітко визначає сигнатуру та тип повертаного значення для функцій. Головна схожість із вказівниками на функції полягає в можливості передавати методи як аргументи. Це дозволяє гнучко реалізувати механізми зворотного виклику (callbacks). Проте між ними є принципова різниця в безпеці коду. Вказівник є простою та незахищеною адресою в оперативній пам'яті. Делегат у C# повністю об'єктно-орієнтований та суворо типізований. Компілятор не дозволить записати в нього метод з іншими параметрами, що захищає програму від критичних помилок пам'яті. Також делегати вміють працювати з методами конкретних об'єктів.
2. Різниця між делегатом та подією (event)Делегат та подія тісно пов'язані, але виконують різні функції захисту даних. Звичайний делегат є відкритою змінною з повним доступом для будь-якого зовнішнього класу. Сторонній код може випадково стерти всі підписки, присвоївши делегату значення null. Також сторонній код може викликати цей делегат напряму в будь-який момент. Подія з ключовим словом event є захищеною оболонкою над делегатом. Вона суворо обмежує права зовнішніх класів. Вони можуть лише підписуватися через оператор += або відписуватися через -=. Сам виклик події дозволено виконувати тільки всередині того класу, де вона була створена.
3. Приклади використання Action<>, Func<> та Predicate<> у кодіВбудовані узагальнені делегати .NET спрощують код та позбавляють потреби створювати власні типи. Делегат Predicate<Student> приймає об'єкт студента, перевіряє умову та завжди повертає bool. Ми використали його в методі FilterStudents для пошуку відмінників або боржників. Делегат Action<Student> має тип повернення void. Він застосовувався в методі PerformOperationOnStudents для виконання масових дій, наприклад, оновлення нотаток усім вибраним студентам. Делегат Func<StudentGroup, string> приймає екземпляр групи і повертає сформований текст. Це дозволило реалізувати метод GenerateReportWithFunc для створення звітів із різним форматуванням.  
4. Робота багатовіщального делегата та його застосуванняБагатовіщальний або multicast делегат працює за принципом послідовного ланцюжка викликів. Він наслідується від системного класу System.MulticastDelegate. Кожен оператор += додає новий метод у спеціальний внутрішній список розсилки (Invocation List). Під час виклику такого делегата програма автоматично виконує всі підключені методи один за одним. У нашому проєкті цей механізм застосовано у методі AttachNotificationHandlers. Ми підвісили одразу кілька різних обробників системи сповіщень на одну подію групи. Завдяки цьому при появі студента одночасно спрацьовує вивід на екран та запис історії логів.  
5. Механізм лямбда-виразів та приклади їх використанняЛямбда-вирази — це лаконічні анонімні функції без імені. Вони пишуться прямо в місці виклику за допомогою оператора стрілочки =>. Під час компіляції програми компілятор C# автоматично перетворює лямбду на звичайний метод класу. У нашій роботі лямбда-вирази активно використовуються для скорочення коду. Першим прикладом є вираз s => s.AverageGrade >= 90 для відбору студентів з високим балом. Другим прикладом є дія s => s.Notes = "Перевірено", яка модифікує властивості об'єктів. Третій приклад — це вираз сортування s => s.FullName для впорядкування студентів за алфавітом. Четвертим прикладом є лямбда g => $"Група: {g.GroupName}" для миттєвого створення заголовка звіту.  
6. Використання подій в системі студентівПодії інтегровані в архітектуру проєкту для розділення логіки даних та логіки сповіщень. У класі StudentGroup ми оголосили події StudentAdded та StudentRemoved. Вони автоматично спрацьовують під час додавання або видалення людей із групи. Сам клас студента містить подію AverageGradeChanged, яка активується всередині методу оновлення оцінки. При додаванні студента клас групи автоматично підписується на його індивідуальну зміну балу. Сигнал про зміну балу проходить через групу і потрапляє в клас NotificationSystem. Це дозволило реалізувати Варіант 1 для червоного сповіщення викладача про появу боржників.  
7. Труднощі під час роботи з делегатами та їх вирішенняВ процесі роботи виникла проблема з компіляцією коду під час спроби викликати подію зміни оцінки прямо з класу меню. Компілятор заблокував цей рядок, оскільки події захищені від примусового виклику ззовні. Для вирішення проблеми ми перенесли запуск події всередину методу OnStudentGradeChanged в самому класі групи. Цей метод має легальний доступ до виклику події групи. Іншою складністю була загроза витоку пам'яті через підписки системи сповіщень на видалених студентів. Ми вирішили це питання, додавши в метод видалення члена групи обов'язкову відписку від подій через оператор -=.

Стало зрозуміло, як будувати архітектуру за допомогою слабкого зв'язку між різними класами. Великою практичною цінністю стало використання стандартних делегатів платформи .NET. Вони повністю ліквідують рутинну роботу зі створення багатьох однакових типів. Також було закріплено навички лаконічного написання коду за допомогою лямбда-виразів та LINQ-запитів. Це є важливим етапом для подальшої розробки програмного забезпечення за спеціальністю.

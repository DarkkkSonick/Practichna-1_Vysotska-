Тема: Робота із структурами
Студентка групи К-321: Висоцька Софія Сергіївна
Питання 1. У чому полягають ключові відмінності між class і struct?
Головна відмінність полягає в тому, що клас є посилальним типом (reference type) і зберігається в купі, тоді як структура — це тип значення (value type), який зазвичай розміщується в стеку. При копіюванні класу передається лише посилання на об'єкт, а при копіюванні структури створюється повна незалежна копія всіх її даних. Крім того, класи підтримують ієрархічне успадкування, а структури — ні.  
Питання 2. Коли доцільно використовувати структури, а коли класи?
Структури найкраще підходять для невеликих, логічно завершених об'єктів з коротким терміном життя, які не потребують успадкування, як-от координати Point або математичні записи ComplexNumber. Класи слід обирати для складних сутностей із великою кількістю даних та складною логікою поведінки, наприклад, для управління навчальною групою чи базою студентів.  
Питання 3. Що таке readonly struct і які переваги він дає?
Це спеціальний вид структури, який гарантує незмінність усіх її полів після створення об'єкта. Використання readonly struct дозволяє уникнути випадкових помилок при зміні даних та дає компілятору можливість оптимізувати роботу з пам'яттю, уникаючи створення зайвих копій об'єкта.  
Питання 4. Наведіть приклади реалізації Equals(), GetHashCode() та IEquatable у ваших структурах.
У розроблених структурах, наприклад у StudentRecord, реалізовано метод Equals(StudentRecord other) для порівняння значень полів Id та FullName, а також перевизначено GetHashCode() через HashCode.Combine для забезпечення унікальності ключів у колекціях. Це дозволяє виконувати порівняння об'єктів без пакування (boxing), що значно пришвидшує роботу програми.  
Питання 5. Які результати ви отримали при порівнянні продуктивності struct vs class? Проаналізуйте їх.
Тестування за допомогою класу PerformanceTest показало, що створення великого масиву структур (StudentRecord[]) відбувається швидше за створення аналогічного масиву класів, оскільки пам'ять виділяється одним блоком. Також структури продемонстрували менше споживання пам'яті, оскільки вони не мають накладних витрат на заголовок об'єкта, що характерно для класів.  
Питання 6. Як інтеграція структур вплинула на вашу систему?
Завдяки впровадженню масивів Point[] та GradeRecord[] у клас StudentGroup, вдалося оптимізувати зберігання історії оцінок та координат лабораторних місць. Метод OptimizeStorage() дозволив компактно розмістити дані в пам'яті, а використання StudentRecord забезпечило швидке копіювання основної інформації про студентів без ризику змінити оригінальні об'єкти.  
Питання 7. Які труднощі виникали під час роботи зі структурами?
Основні труднощі були пов'язані з неможливістю успадкування та необхідністю ручного перевизначення всіх операторів порівняння та методів перевірки на рівність для коректної логіки програми. Також важливо було контролювати відсутність пакування (boxing) при викликах методів, що потребувало чіткої реалізації інтерфейсу IEquatable<T>.  
Питання 8. Що нового ви дізналися під час виконання цієї практичної роботи?
Робота допомогла глибше зрозуміти механізми керування пам'яттю в .NET, навчитися створювати ефективні типи даних та використовувати інструменти діагностики для вимірювання швидкодії коду. Було засвоєно практичні навички оптимізації існуючих систем через заміну частин посилальних даних на структури значень.
